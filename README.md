# FT 数据分析工作台

这是一个完全在本机浏览器运行的 FT 数据分析工具，不会上传测试数据，也不需要安装 Python 或其他依赖。

## 使用方法

### 界面统一与项目交接（v1.56）

- 简易 / 专业模式改为分段按钮，滑块平滑切换；沿用当前分析结果，不因切换重新统计。
- Fail 分布左右区域独立滚动，桌面高度随浏览器可用区域调整；滚动条统一为细圆角样式。
- 移除模式说明段落与批次良率面板展示，导入异常仅显示简短文件数量提示；批次计算、子批筛选和报告导出仍保留。
- 保留完整测试统计、规格与良率模拟面板，以及顺序图、直方图；已撤回紧凑工具带布局。
- 开发接续先读 `AGENTS.md`、`docs/PROJECT_STATUS.md`、`docs/BUSINESS_RULES.md`；根目录旧 `PROJECT_STATUS.md` 仅作历史记录。

### 末轮空封与复测链（v1.55）

- 规格与良率模拟中的 LSL、USL 上下箭头调节步进为 0.1。

- 有 RT 时，各子批以当前已导入的最高 RT 轮次统计空封；无 RT 时取初测。按轮次排序，不按导入顺序，不累加各轮空封。导出保留当前截止轮次、逐轮空封和分片文件数；当前截止轮次不代表批次已结束。v1.56 起页面隐藏批次面板。
- CSV 内容做 SHA-256 去重（统一换行/BOM），结合解析出的阶段和文件角色判断。改名、重复选择、压缩包内外同内容的相同阶段 CSV 不重复加入；不同阶段不互相去重。XLSX 仍使用原有导入规则。
- 同子批、同阶段的分片，测试项和程序兼容且 Site/Serial 完整、不重叠时合并。编号重启、记录交叠、程序不一致时不自动拼接。不同 FT 阶段不能直接合并为一次初测。
- 缺轮时保留来源和当前截止轮次，但不推算跨轮落料遗失，也不输出确定批次良率。

### 空封与两种批次良率

- LX3418 / LX3418C 的 ETS、PowerTECH 明细按前置 OS 实测值识别空封：至少两个不同 OS 项命中特征电压，容差 ±0.05V。ETS 的 VDD/V1/V2/V3 目标分别为 −1.982/−2.065/−2.058/−2.023V，PowerTECH 四项目标为 −2.9V。该容差是当前实现值，依据已提供样本验证；其他产品/格式尚不自动识别。
- 后置 OS、缺失值、QA 与 Loop 不参与空封判定，不以 Bin 编号直接判定。Fail 明细显示空封标记，可搜索“空封”，导出保留原测试结果与空封标记。
- 包含空封良率 = 累计通过 / 初测投入；不包含空封良率 = 累计通过 /（初测投入 − 末轮空封）。末轮空封只扣一次，不累加各轮，总批次使用数量加权。上方测试事件指标仍保留原口径。
- 无有效分母、复测链异常或扣除后通过数大于投入时，不输出无依据的良率。报告保留批次试算及核对说明；v1.56 起页面不再展示该面板。

### 子批次与总批次良率（v1.53）

- 导入后自动读取 Sub Lot Number / MES LotID，按“产品 + 客户批号 + 子批号”分组；分析范围增加子批次选项，选中后汇集该组文件。缺少子批号的文件独立保留，不能跨文件推算复测。
- 子批次核对保留初测投入、复测恢复、累计通过、末轮 Fail、待确认遗失差额、试算良率及逐轮来源和数量；v1.56 起仅保留计算与导出，隐藏总览中的表格。
- 试算假设每轮 Pass 退出后续复测、全部 Fail 应进入下一轮。差额 = 上轮 Fail − 下轮投入；正差额保留在初始投入分母中，尚不代表确认掉料。没有下一轮时，末轮 Fail 仍为不良，不计为遗失。
- 良率试算 =（初测 Pass + 各轮复测 Pass）/ 初测 CSV 原始投入。尚未自动识别调机剔除或还原工厂投料量，因此不能当作已确认的工厂最终良率。
- 总批次以“产品 + 客户批号”汇总，使用各子批累计通过之和 / 初测投入之和，不平均百分比。不同总批次单独显示；产品或客户批号缺失时不跨子批汇总。
- QA、Loop 不计生产恢复；BIN/阶段不明文件单列待确认。多个初测、同轮文件无法安全合并、轮次缺失、时间倒置、轮内重复 Site/Serial、复测投入超过上一轮 Fail 时，不生成确定的链路良率；对应总批次标待确认，只展示可核对子批小计，不能跨子批抵扣差额。
- 上方八张指标卡和 Fail 分析保持测试事件口径；批次表是独立的复测链试算，避免把两种分母混用。简易与专业导出均包含批次表、逐轮核对及排除文件。

### 常规操作

1. 双击 `启动FT分析工具.bat`，或直接双击 `index.html`。
2. 将一个或多个测试机 CSV、Loop 测试 XLSX、工厂良率 XLSX、ZIP、7z、RAR 压缩包或整个文件夹拖到页面导入区。文件夹会递归读取全部子目录中的支持文件，压缩包中的全部 CSV 会被自动读取；软件会自动区分 Loop 测试 XLSX 与工厂良率 XLSX。
3. 在“总览”查看良率、Fail Pareto 和测试顺序良率趋势；点击任一 Pareto 柱会在下方联动显示该测试项的 Fail 构成、批次影响与超限方向，可按排名切换上一项或下一项。
   - 默认“简易模式”保留产品名称、测试记录、Pass（含良率）、Fail、首要 Fail 项、单颗测试时间、UPH、日产出八张指标卡，以及前五项 Fail 的影响；良率损失以“该项 Fail 次数 / 总记录数”的百分点表示，不等于承诺可恢复的良率。
   - 点击“专业模式”或“展开专业分析”，显示完整指标、Pareto、趋势、分布、稳定性、明细、文件对比与数据审计。
   - 两种模式都按当前测试事件统计，不再提供正式初测/工厂最终的口径切换；复测与 Loop 事件不能当作唯一产品数。工厂报告仍可在专业数据审计中作为参考。
   - 模式切换只展开或收起当前内容，复用统计结果、选中项和缓存；新增/移除文件或修改分析范围后才重新分析数据。
4. 在联动单项分析卡点击“查看超限分布”或“查看 Fail 明细”，可直接进入对应测试项的分布图或逐颗记录。分布图中红色点/柱表示超出规格；拖动 LSL/USL 虚线或输入目标规格，可实时模拟良率变化。
5. 在“Pass 稳定性”查看各测试项均值、标准差、Ppk、规格利用率及参数趋势。普通生产明细只使用 Pass 记录，Loop XLSX 则使用全部循环记录，确保失败循环中的参数漂移仍可分析。
   - Fail 分布与 Pass 稳定性使用同一个当前测试项；在任一界面选择测试项，切换到另一界面时会自动显示同名项目。
6. 在“Fail 明细”按测试项筛选每条失效记录；点击 Fail 测试项名称可返回对应分布图。
7. 在“文件对比”比较 FT、FT1、FT2、RT 或不同批次；文件会按名称末尾的测试时间自动排序。
   - “分析范围”选择框会展开显示完整 CSV 文件名；压缩包文件只省略重复的压缩包与内部目录前缀，不改变实际数据来源。
8. 简易模式点击“导出简易报告”仅导出核心指标与前五项 Fail；专业模式点击“导出分析结果”生成包含详细分析的 CSV 报告。
9. 压缩包内的 `*_Summary.csv` 会作为独立汇总文件读取，不计入逐颗记录，也不会出现在默认总览；需要时在“分析范围”中选择对应的 Summary 查看。
10. 打开“数据审计”查看字段缺失、疑似重复标识、文件角色及其判定依据、规格冲突和生产数量流转；审计结果只提示风险，不会自动删除或改写原始记录。
11. 打开“更新日志”可查看版本与对应功能变更；后续更新将持续记录在该页签。

维护更新日志时，在 `app.js` 顶部的 `RELEASE_NOTES` 中新增一条版本记录即可；最新版本放在数组最前面，并将 `index.html` 页脚版本号同步更新。

## 版本与 Git 管理

- 每次功能更新都同步更新：`app.js` 内的 `RELEASE_NOTES`、`index.html` 的页脚与静态资源版本号、以及本说明文件（如有使用方式变化）。
- 每个可交付版本创建一个 Git 提交，并打上同名标签，例如 `v1.40`；这样可随时查看差异或回退到任一稳定版本。
- 上传 GitHub 前，在项目目录执行 `git remote add origin <你的仓库地址>`，再执行 `git push -u origin main --tags`。后续每个版本提交和标签推送后，GitHub 即会保留完整更新记录。

## 当前支持的测试明细格式

- **ETS 格式**：数据表头包含 `Date`、`Site`、`Serial`、`HBIN`、`SBIN`，文件尾部可包含 `SoftBin Total Summary`。
- **PowerTECH 格式**：数据表头以 `Site #`、`Serial #`、`SBin`、`HBin` 开始，测试项目由前面的 `Test Name` 和 `Test Number` 行定义。
- **DataLog 格式**：文件顶部包含 `Data Log Site`，测试定义由 `TestItem`、`HiFBin`、`LoFBin`、`LimitH`、`LimitL` 和 `Unit` 行组成，数据区以 `X-Y,SBin,TestResult` 开始。
- **ATX Datalog 格式**：数据区以 `Device#、Site、X-coordinate、Y-coordinate、Pass Fail、Hard Bin、Soft Bin、Test Number` 开始，后续 `Test Name`、`Units`、`Lower Limit`、`Upper Limit` 行定义测试项目及规格。
- **Loop XLSX 格式**：识别以 `Test Name`、`Test Number`、`Lower Limit`、`Upper Limit`、`Units` 定义参数，并以 `Site #、Serial #、SBin、HBin` 开始数据区的宽表循环测试文件；数据区每行作为一次 Loop 记录分析。
- **Summary 汇总报告**：识别首行 `Summary Report` 的固定宽度文本报表，读取 Pass、Fail、Total、Yield、SBin/HBin、FailCount 和模块测试时间。Summary 采用独立视图，不会作为逐颗记录重复累加。
- 软件会自动识别格式，不需要手动选择；五种明细格式与 Summary 汇总报告可同时导入。
- 五种格式都会读取各自的上下限和单位定义，并将元数据转换成统一字段。
- ATX Datalog 中同名测试项重复出现时，会按出现顺序增加 `[1]`、`[2]` 后缀，避免前后测量阶段的数据被合并。

## 文件名阶段与时间

- 文件名中独立的 `FT`、`FT1`、`FT2` 等字段用于识别初测阶段。
- 文件名中独立的 `RT`、`RT1` 等字段统一标记为“复测”。
- 软件提取文件名中的 `YYYYMMDDHHMM` 或 `YYYYMMDDHHMMSS` 时间，并据此排列文件筛选、文件对比、良率趋势和参数分布；没有可识别时间的文件排在最后。

## ZIP / 7z / RAR 支持

- 支持常见的 Store 和 Deflate ZIP 压缩方式，可读取子文件夹内的 CSV。
- 支持标准 7z 与常见 RAR/RAR5 压缩包，并递归读取各层文件夹内的 CSV。首次读取 7z 或 RAR 时会从软件自带的 `vendor` 目录加载离线解压组件。
- 支持 UTF-8 和常见中文文件名编码。
- 压缩包只在浏览器内存中解压，不会把文件释放到磁盘或上传到网络。
- 不支持加密或分卷压缩包；ZIP64 暂不支持。
- 单个 CSV 解压上限为 256 MB；一个压缩包内 CSV 总解压上限为 512 MB，避免异常压缩包占满内存。

## 指标说明

- **良率**：Pass 记录数 / 总测试记录数。ETS 优先按 Soft Bin 的 P/F 标记判断，缺少标记时按 `SBIN=0`；PowerTECH 和 DataLog 按 `SBin=1` 判断。
- **分析模式**：简易和专业模式只改变展示深度，总览统一按测试事件计算。专业审计中的生产流转和工厂数据是参考信息，不替换总览良率。
- **Loop 数据口径**：Loop XLSX 的每一数据行代表一次循环测试事件，可用于参数趋势、稳定性和 Fail 分布分析；它会明确标记为“循环测试”，并从正式生产投入及工厂最终良率口径中排除。
- **工厂 XLSX 锚定**：识别包含“测试投入、测试产出、测试良率”的工作表，按子批号、产品型号和客户批号匹配初测 CSV。若同一批次无法唯一匹配，软件不会自动采用该行。
- **正式生产区间**：有唯一工厂投入锚点时，从初测 CSV 尾部保留相同数量的记录，并显示反推起始序号、排除数量与高置信度标记；用户可人工调整起始序号，导出报告保留完整审计表。
- **Hard Bin 分类**：主产品产出按 HBin1 统计，HBin8 单独列示，HBin3 暂归为电性，HBin5 暂归为 O/S，其余 HBin 归入其他处置。映射来自目前样本规律，最终仍应按产品流程卡确认。
- **复测与 QA**：名称含 RT 的复测文件不会再次计入初测投入；名称含独立 `QA` 字段的验证文件从工厂口径排除。由于目前 CSV 缺少可跨文件追踪的稳定唯一产品 ID，软件不会用复测结果自动覆盖初测结果，也不会把估算值冒充最终工厂良率。
- **最终结果推算**：工厂报告已匹配时，`推算恢复 = 工厂最终产出 - 正式初测 HBin1`，`最终不良 = 工厂投入 - 工厂最终产出`。这是数量流转推算，不代表已建立逐颗复测关联。
- **Fail 归因**：按每条记录的 SBIN 对应测试项统计。偏低/偏高由实测值与上下限比较得到。
- **Pareto 联动单项分析**：总览默认选中 Pareto 第一项；点击任一柱条只切换下方分析卡，不自动跳转页签。分析卡显示该项占全部 Fail 的比例、占整批测试记录的比例以及偏低/偏高方向，并提供上一项、下一项、超限分布和 Fail 明细入口。
- **Fail 分布**：点击左上角“测试项”下拉框可展开当前范围内的全部测试项目，包括没有归因 Fail 的项目。选择后使用该项目的全部有效实测值绘制顺序图和直方图，规格内为蓝色、超限为红色；多文件规格不同时按每个文件自己的上下限判定。
- **测试项菜单分组**：Fail 分布默认只列出有归因 Fail 的项目；点击菜单底部“显示全部测试项”后，无 Fail / 仅 Pass 项目会在独立分组中显示。从 Pass 稳定性联动选择无 Fail 项时会自动展开该分组。
- **规格区聚焦**：有完整 LSL/USL 时，分布图默认以规格区为中心显示，避免极端 Fail 值把规格线压缩到看不清。视窗外异常值会压到顺序图边界，并单独显示低值/高值数量；直方图只统计当前视窗。点击“显示全部范围”可恢复完整极值范围。
- **偏低/偏高占比**：Fail 分布左侧列表同时显示方向数量及其占该测试项 Fail 总数的比例；缺少实测值或无法判断方向的记录不计入偏低/偏高。
- **Fail 批次占比**：Fail 总数下方显示该测试项 Fail 数量占当前分析范围总测试记录数的比例；选择单文件时代表该文件，选择全部文件时代表汇总批次。
- **单颗测试时间**：优先读取记录表中的 `Test time`、`Test Time(ms)` 或 `Elapsed Time(ms)` 字段并计算有效记录均值；仅有文件级测试时间时使用文件级数值。没有明确测试时间字段时显示 `—`，不会用开始/结束时间推测。
- **UPH**：按 `3600 ÷ (单颗测试时间 ms + 150 ms Index 时间) × 1000` 计算。
- **日产出**：按 `UPH × 20 小时 × 85% 稼动率` 计算。汇总多个文件时，单颗测试时间按有效记录加权平均。
- **Summary 独立视图**：软件不会将 Summary 与同压缩包或单独导入的明细 CSV 自动关联。只有在“分析范围”中主动选择某个 Summary 后，才显示报告良率、SBin/HBin、FailCount、模块测试时间、理论 UPH 和日产出。
- **Summary 内部校验**：选择 Summary 后会核对其自身的 `Pass + Fail = Total`、`Yield = Pass / Total`、Bin 合计和 FailCount 合计；因为报告没有逐颗实测值，Fail 数值分布、Pass 稳定性和逐颗 Fail 明细会停用。
- **Summary 产能说明**：模块测试时间会按报表中的各模块时间相加；由此计算的 UPH/日产出标记为理论估算，仍需结合并行测试和实际 Handler 节拍确认。
- **规格良率模拟**：调整单个 Fail 测试项的 LSL/USL 后，软件实时估算预计 Pass、总良率、恢复数量和新增 Fail。模拟只改变所选测试项的规格判定，其他 Fail 原因保持不变；原规格位置的模拟结果始终等于当前实际良率。
- **多规格限制**：当多个明细文件对同一测试项使用不同上下限时，规格拖动功能会暂停。请先在“分析范围”中选择单个文件，以免使用一组规格产生误导结果。
- **DataLog Fail 归因**：当一个 SBin 对应多个测试项时，软件依据该 SBin 的 HiFBin/LoFBin 映射和实测超限情况，归因到第一个匹配的超限测试项。
- **Ppk**：普通生产数据仅使用 Pass 记录，Loop 数据使用全部循环记录（含失败循环）。前者是通过样本的条件统计，后者是重复测量统计，均不应直接当作整批生产过程能力结论。样本数少于 30 时仍显示数值，但状态标为“样本不足”。
- **稳定性状态**：Ppk ≥ 1.33 为“稳定”；1.00–1.33 为“关注”；Ppk < 1.00 为“风险”。该状态用于快速筛查，最终结论仍需结合量测系统、抽样方案和内部工程规范。
